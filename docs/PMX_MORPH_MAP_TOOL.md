# PMX 表情映射表与标准化工具

MMD 通用动作（面部表情、口型、眨眼类 VMD）**只按表情名**驱动模型：动作里有
`まばたき`、`あ`、`ウィンク２` 这些关键帧，模型就必须有同名的 morph，否则 MMD
直接忽略。第三方模型（尤其是 VRoid → Vroid2Pmx 导出）经常对不上：

- 缺少标准名，只有导出名（`Fcl_EYE_Close`、`ｳｨﾝｸ２右`…）；
- 名字对但**内容不完整**：例如 `まばたき` 只有顶点形变，真正完整的表情叫
  `まばたき連動`（还包含眼睑骨骼与眉毛的联动）；
- 同一个表情写成半角/全角混排（`ウィンク２` / `ウィンク2` / `ｳｨﾝｸ２右`），
  而不同动作用的写法不一样；
- 可用的素材被藏在 `システム`（panel 0）里，表情列表看不到。

本工具用一张 **表情映射表（JSON）** 描述「标准表情 ← 由哪些原有表情按什么权重
复制/组合」，然后**生成一个新的 PMX**（原文件不动）。生成结果全部是 group
morph，只引用模型里已有的表情，不新增美术数据。

**标准名的依据是参考模型 `洛恩.pmx`**（64 个表情，全部是列表里可见的标准名）。
内置目录（`catalog`）据此分成两档：

- `tier=standard`（63 项）：与参考模型同名的标准名，如 `ウィンク２`（全角数字）、
  `ぺろっ`、`悲しむ`、`怒り目`、`ジト目`、`眼角上/眼角下`、`下眼上`、`恥ずかしい`、
  `口横狭め`、`舌広げ`、`ワ２`、`い１/い２/い３`、`あ２`、`にやり２/にやり３`、
  以及眉/上/下/前/困る/にこり/怒り 的左右版本；
- `tier=extended`（41 项）：动作语料里常见、但参考模型没有的名字，如 `にっこり`、
  `はぅ`、`星目`、`はぁと`、`はちゅ目`、`目上/目下`、`瞳小/瞳大`、`白目`、
  `ハイライトなし`、`ｷﾘｯ`、`なぬ！`、`▲`、`∧`、`□` 等。

## 交付物

| 文件 | 说明 |
| --- | --- |
| `tools/pmxlib.py` | PMX 2.0/2.1 读写库。逐段解析，未改动段落沿用原始字节，保证**未修改即逐字节往返** |
| `tools/pmx_morph_tool.py` | 命令行工具：`catalog` / `dump` / `check` / `apply` / `draft` / `verify` / `simulate` / `selftest` |
| `tools/morph_maps/luotianyi_luoxijixian.json` | 洛天依·洛希极限 的表情映射表 |
| `docs/PMX_MORPH_MAP_TOOL.md` | 本文档 |

## 快速开始

```bash
# 1. 看参考标准名 / 模型现在有哪些表情
python tools/pmx_morph_tool.py catalog --tier standard
python tools/pmx_morph_tool.py dump "洛天依洛希极限.pmx" --groups

# 2. 只看映射表会做什么（不写文件）
python tools/pmx_morph_tool.py check "洛天依洛希极限.pmx" tools/morph_maps/luotianyi_luoxijixian.json

# 3. 生成标准化模型（默认输出到同目录的 xxx_标准表情.pmx）
python tools/pmx_morph_tool.py apply "洛天依洛希极限.pmx" \
    tools/morph_maps/luotianyi_luoxijixian.json -o "洛天依洛希极限_标准表情.pmx" \
    --report "标准化报告.txt"

# 4. 结构自检 + 用真实动作模拟验证
python tools/pmx_morph_tool.py verify "洛天依洛希极限_标准表情.pmx"
python tools/pmx_morph_tool.py simulate "洛天依洛希极限_标准表情.pmx" "Facials.vmd"
```

常用开关：

- `--keep-original`：把被改写的原表情**保留成可见表情**（原名加后缀，仍在表示枠里）。
  默认不保留，详见下一节；
- `--keep-original-suffix _元`：保留时使用的后缀（默认取映射表 `backup_suffix`）；
- `--exact-only`：只生成 `quality: exact` 的条目，跳过所有近似映射；
- `--with-disabled`：连映射表里 `enabled: false` 的条目也生成（例如 `照れ`）；
- `--on-existing keep|replace|skip|rename`：临时覆盖同名表情的处理策略；
- `--dry-run`：只打印计划。

## 原表情怎么处理（默认不保留）

标准名要"就地"落到原索引上（这样 MMD 的表情顺序不变、引用不用改），而原表情的
数据有时还被别的表情引用（典型例子：`まばたき連動` 依赖 `ウィンク２`、`ｳｨﾝｸ２右`
的顶点数据）。工具的处理规则：

| 情况 | 默认行为 | `--keep-original` |
| --- | --- | --- |
| 原表情数据没有任何表情引用 | **直接丢弃**（如 `まばたき`、`笑い` 的旧顶点数据，内容等价于组合结果） | 保留为可见表情 `～～_頂点` |
| 原表情数据仍被其它表情引用 | 复制到**内部槽位**：panel 0、**不加入表示枠**，MMD 界面里看不到，但引用它的表情照常工作 | 保留为可见表情 `～～_頂点`，沿用原面板并留在表示枠 |
| 导出器生成的 `～～連動` 组合（内容已被标准名覆盖） | 用映射表的 `hide: true` 移出表示枠 + panel 0（动作仍可驱动它） | 同样处理（可在映射表里去掉 `hide`） |
| 同一效果的其它写法（半角数字、半角片假名） | 新建为 panel 0 的别名，**不进表示枠** | 同 |

所以默认生成结果的 4 个表情页（眉/目/口/その他）里只有标准名和模型本来就有意义的
表情，不会出现一堆 `～～_頂点`、`～～連動`、半角写法。

## 映射表格式

```jsonc
{
  "format": "mmd-pmx-morph-map",
  "id": "luotianyi_luoxijixian",
  "title": "洛天依·洛希极限 — MMD 通用动作表情映射表",
  "reference_pmx": "洛恩.pmx",                  // 标准名的依据
  "model": { "name": "洛天依_洛希極限", "sha256": "855709fa…" },
  "defaults": {
    "on_existing": "replace",        // 同名表情：keep / replace / rename / skip
    "flatten_groups": true,          // 把来源里的 group morph 展开成底层表达式
    "panel_for_aliases": 0,          // 别名面板（列表里不显示但能被动作驱动）
    "add_to_display_frame": "表情",  // 生成的表情追加到哪个表示枠（null = 不追加）
    "keep_original": false,          // 是否保留被改写的原表情
    "backup_suffix": "_頂点",        // 保留/内部槽位使用的名字后缀
    "backup_panel": 0                // 内部槽位的面板
  },
  "morphs": [
    {
      "name": "ウィンク２",            // 目标标准名（MMD 动作按这个名字驱动）
      "name_en": "Wink2L",            // 英文名（写进 PMX 的英文名字段）
      "panel": "目",                  // 眉 / 目 / 口 / その他 / システム（或 0-4）
      "quality": "exact",             // exact / approx / unmapped
      "note": "…",                    // 报告里会打印，写清依据
      "sources": [                    // 复制或组合的来源，权重可正可负
        { "morph": "ウィンク２連動", "weight": 1.0 }
      ]
    },
    {
      "name": "ウィンク2",             // 别名写法
      "panel": "システム",
      "alias": true,                  // 不进表示枠
      "sources": [{ "morph": "ウィンク２連動", "weight": 1.0 }]
    },
    {
      "name": "まばたき連動",           // 已有表情：只调面板/移出表示枠，不改内容
      "panel": "システム",
      "on_existing": "keep",
      "hide": true
    },
    {
      "name": "照れ",                   // 也可以直接生成材质表情（type 8）
      "panel": "その他",
      "material": { "operations": [
        { "material": "00_Face", "mode": "mul", "diffuse": [1.0, 0.86, 0.86, 1.0] }
      ]}
    }
  ]
}
```

来源条目的写法：

| 写法 | 说明 |
| --- | --- |
| `{"morph": "名前"}` | 按 PMX 本地名匹配（先精确，再全半角/兼容归一化并给出告警） |
| `{"en": "Fcl_EYE_Close"}` | 按英文名匹配 |
| `{"index": 58}` | 按序号匹配（模型改版后容易失效，仅作兜底） |
| `{"pattern": "*連動"}` | 通配符匹配，命中多个时取第一个并告警 |
| `"weight": 0.6` / `-0.8` | 组合权重，可负（用来抵消或反向近似） |

`quality` 的约定：

- `exact`：名字与形态都对应得上；
- `approx`：形态不同、用近似来源顶替，报告里会标 ⚠，可被 `--exact-only` 跳过；
- `unmapped`：模型根本没有可用来源，默认 `enabled: false`。**不生成等价于动作
  无效果**（MMD 会忽略不存在的表情名），所以这类条目只在报告里说明原因。

## 从本工程代码里确认的硬约束

生成结果必须遵守 MMD 的真实行为，以下几条是从本仓库实现里读出来的：

1. **group morph 只解析一层**。`src/model/morph_apply.cpp`（骨骼、材质）与
   `src/model/model_skinning.cpp`（顶点）都对引用目标只取一次条目，不递归。
   所以工具默认把来源里的 group 递归 `flatten` 成底层顶点/骨骼/材质表情，并把
   被改写表情的引用改指内部槽位，`verify` 也会把 `group 套 group` 报为警告。
2. **PMX 骨骼 morph 的旋转量是四元数**（4 个 float），不是欧拉角，见
   `include/mikudancestudio/subrecord_layout.hpp` 的 `PmxBoneMorphEntry`
   （`boneIndex + translation[3] + rotation[4]` = 32 字节）。按 3 个 float 读会直接
   错位，`tools/pmxlib.py` 已按四元数处理。
3. **表情名用 Shift-JIS 匹配**。`src/model/pmx_load.cpp` 载入时把名字写入 20 字节
   字段（`WideToSjis(..., 0x14)`），VMD 里是 15 字节 Shift-JIS。名字必须能用
   Shift-JIS 表示且不超过 19 字节，`verify` 会检查（`simulate` 也按字节匹配）。
4. **panel 0（システム）不出现在表情列表**：`src/model/post_load_init.cpp` 只把与
   下拉框面板号相等的表情填进列表。别名因此默认放 panel 0 —— 不占界面，照样能被
   动作驱动。
5. **材质 morph 的材质索引 -1 表示全部材质**（`morph_apply.cpp` 的
   `AccumMatMorph`），映射表里写 `"material": "*"` 即可。
6. **权重可以是负数**：模型自带的 `にこ` 就有 `口横広げ×-0.3`，所以"反向近似"
   （如 `口横狭め = 口横広げ×-0.8`）和"抵消"（`カメラ目線`）都是合法做法。

## 洛天依·洛希极限 的处理结果

原模型 267 个表情 → 生成后 334 个（150 条映射：精确 89 / 近似 55 / 无法提供 6）。

| 动作 | 数量 | 说明 |
| --- | --- | --- |
| 新增 | 63 | 补齐 63 个参考标准名里缺的部分，以及动作里用到的别名写法 |
| 就地改写 | 6 | `まばたき` `笑い` `ウィンク` `ウィンク右` `ウィンク２` `ｳｨﾝｸ２右` |
| 内部槽位（界面不可见） | 4 | `ウィンク_頂点` `ウィンク右_頂点` `ウィンク２_頂点` `ｳｨﾝｸ２右_頂点` |
| 数据丢弃 | 2 | `まばたき` `笑い` 的旧顶点数据（内容等价于组合结果，无其它表情引用） |
| 保留原样（含 7 个仅调面板/移出表示枠） | 74 | 名字与内容本来就符合标准，以及导出器生成的 `～～連動` |
| 未生成 | 7 | `照れ`（可选开启）`涙` `涙１` `涙２` `歯無し上/下` `□` |

关键处理：

- `まばたき` / `笑い` / `ウィンク` / `ウィンク右` / `ウィンク２` / `ｳｨﾝｸ２右`
  原来**只有顶点形变**，完整表情是 `～～連動`（顶点 + 眼睑骨骼 + 眉毛 + 瞳孔）。
  工具把这 6 个标准名就地改写成展开后的完整组合；被其它表情引用的 4 份顶点数据
  转存到内部槽位，`～～連動` 的引用同步改指槽位，保持有效。
- **全角数字才是标准写法**（参考模型 `ウィンク２` `あ２` `にやり２` `にやり３`
  `ワ２` `い１/い２/い３`）：这些作为可见标准名新建；半角写法
  （`ウィンク2` `あ2` `にやり3` `ｳｨﾝｸ２`…）作为 panel 0 别名，动作照样能驱动。
- **字形不同就是不同的表情**：`∧`(U+2227) 与模型里的 `Λ`(U+039B)、`ジト目` 与
  `じと目`、`ハイライト消/無し` 与 `ハイライトなし`、`前` 与 `眉手前`，都补了同名表情。
- 参考模型里 `じと目`(Eye_Jito) 与 `ジト目`(Eye_Tired) 是两种表情、`悲しむ`(Eye_Wail)
  和 `怒り目`(Eye_Hostility) 也各有专门形状；本模型没有这些专门形状，用模型自带的
  `じと目` / `ｷﾘｯ` 近似，并在报告里标 ⚠。
- `カメラ目線`（ザムザ_facial 里 34 个有效关键帧）：参考模型也没有这个形状。用
  **视线反向抵消**近似 —— 把 `目上/目下/目頭広/目尻広` 以 -1 权重相减，动作同时驱动
  视线表情时把视线拉回正前方（VRoid 脸的默认视线方向），单独驱动则无效果。
- `照れ`：参考模型的做法是"专门的照れ材质（默认 alpha=0）+ 加法显现"；本模型没有
  这种材质，原有的 `照れ` 是一条"0 条材质操作"的空材质表情。映射表保留了一条
  可选的整脸材质染色（默认关闭），但整体泛红不等于腮红，要做真正的腮红需要新增
  材质/贴图，超出本工具范围。

用本机动作库做的模拟验证（`simulate`，只统计**非零权重**的表情名，也就是动作真正
驱动到的表情）：

| 动作 | 有效表情名 | 原版缺 | 标准版缺 |
| --- | ---: | ---: | ---: |
| Facials.vmd（Romeo and Cinderella） | 6 | 0 | 0 |
| Motion01 / Motion02.vmd（1000年生きてる） | 10 / 11 | 1 / 1 | 0 |
| ワールドイズマイン.vmd | 8 | 0 | 0 |
| ワールドイズマイン（男性モデル向け）.vmd | 8 | 0 | 0 |
| BEHIND.vmd / FRONT.vmd（ザムザ） | 11 / 10 | 0 | 0 |
| ザムザ_facial_BY_M.Liang.vmd | 7 | 1（カメラ目線） | 0 |
| キュートなカノジョ.vmd / 表情+目线.vmd | 11 / 17 | 1 / 1 | 0 |
| **全部动作合并** | **21** | **3**（カメラ目線、にやり、え２） | **0** |

原来的缺口是"模型里根本没有这个名字"（`にやり`、`え２`、`カメラ目線`）；现在都补上了。
更重要的是**已有名字的内容**变完整了 —— 同一个动作在 `まばたき = 1.0` 时的差别
（`simulate` 第 4812 帧）：

```
原版    まばたき 1.000  #58   vertex   2188 顶点   0 骨骼
标准版  まばたき 1.000  #270  group   11147 顶点   2 骨骼
```

（`simulate` 打印的"整条动作用到 N 个表情名"会把权重 0 的占位键也算进去，那些名字
不影响画面，不必强求；上面表格按非零权重统计。）

## 验证

```bash
python tools/pmx_morph_tool.py selftest      # 合成 PMX 的解析/生成/回读闭环自检
python tools/pmx_morph_tool.py verify  model.pmx
python tools/pmx_morph_tool.py simulate model.pmx motion.vmd [--frame N] [--json out.json]
```

- `selftest` 覆盖：逐字节往返、group 展开与权重合并、别名面板、材质 morph
  序列化、循环引用检测、内部槽位与引用改指、`--keep-original` 可见保留；
- `verify` 覆盖：表情重名、嵌套 group、越界索引（顶点/骨骼/材质/刚体/表示枠）、
  索引宽度上限、Shift-JIS 名字长度；
- `simulate` 按 MMD 的匹配与展开规则，用真实 VMD 逐条列出「这个表情名在模型里命中
  哪个表情、影响多少顶点/骨骼/材质」，并给出整条动作的表情名覆盖率。

## 限制

- 只改表情，不动顶点、材质、骨骼与物理；材质表情只有在映射表里显式写了
  `material` 才会生成。
- 近似条目（`approx`）只保证"名字对得上、有合理形变"，形态是否好看需要目视确认；
  用 `--exact-only` 可以只保留确定对应得上的部分。
- `形状变化` 版 PMX 请另行处理（映射表按原版名字编写，改版模型先 `check`）。
- 生成结果只写新 PMX，原始文件不会被覆盖；建议先把新文件放在原模型同目录，贴图
  相对路径才有效。

## 复用到其它模型

```bash
python tools/pmx_morph_tool.py draft "别的模型.pmx" -o tools/morph_maps/other.json
```

`draft` 会按内置目录（标准名优先）自动起草一份映射表：同名直接复制、能按别名/
英文名近似的标成 `approx`、找不到来源的标成 `unmapped` 留空，再人工补齐 `sources`、
用 `check` 复核即可。
